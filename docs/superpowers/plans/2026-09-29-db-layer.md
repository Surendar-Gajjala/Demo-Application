# DB Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PostgreSQL schema, demo seed data, reference BOM queries and a verification script, runnable with Docker Compose.

**Architecture:** Flyway SQL migrations in `db/migrations` applied by a one-shot `flyway` container against a `postgres` container with a named volume. Reference recursive CTEs in `db/queries`. `db/tests/verify.sql` asserts constraints and traversal inside a rolled-back transaction.

**Tech Stack:** PostgreSQL 16, Flyway 10 (Docker image), Docker Compose v2, psql.

**Spec:** `docs/superpowers/specs/2026-09-29-db-layer-design.md`

## Global Constraints

- Lifecycle values: `DESIGN`, `PRODUCTION`. Item types: `ASSEMBLY`, `FINISHED`.
- Enums stored as `VARCHAR` + `CHECK`; PKs `BIGINT GENERATED ALWAYS AS IDENTITY`.
- Multi-parent BOM allowed; self-edges, duplicate edges and cycles rejected by the DB.
- Seed edges reference items by `item_number`, never by hard-coded id.
- No git repository exists yet; commit steps are skipped until one is created.
