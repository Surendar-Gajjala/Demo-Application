# Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spring Boot REST backend for Items, Parts, Sites, Item BOM and Dashboard on top of the existing PostgreSQL schema.

**Architecture:** Layered Controller → Service → Repository. Entities map the Flyway-managed tables (`ddl-auto=validate`). BOM traversal uses one native recursive CTE per request; `BomTreeBuilder` turns the DFS-ordered rows into a nested tree.

**Tech Stack:** Java 19, Spring Boot 3.3.5 (Flyway 10, Hibernate 6.5), springdoc-openapi 2.6.0, Testcontainers PostgreSQL 16. Built and tested inside `maven:3.9-eclipse-temurin-19` (no local JDK 19).

**Spec:** `backend/CLAUDE.md` (plus `db/CLAUDE.md` for the schema).

## Global Constraints

- Package root `com.demo.application`; layer packages per spec section 3.
- DTOs are records; controllers never expose entities.
- `ddl-auto=validate`; migrations only in `db/migrations`.
- Errors are RFC 7807 `ProblemDetail`; status mapping per spec section 9.
- `page` 0-based, `size` default 20, clamped to 1..100; single `sort=field,dir` with whitelist.
- Tests run against real PostgreSQL (Testcontainers), never H2.
- Spring Boot 3.3.x instead of 3.2.x: keeps Flyway on major 10, same as the Compose `flyway` service that created the history table.
